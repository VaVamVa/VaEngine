## Compact Log #1 — Geometry.h 정립(Sphere → AABB/OBB/Capsule/Quad), Plane 분리

### 수정 파일

- `Engine/Public/Math/BoundingVolume.h` → `Engine/Public/Math/Geometry.h`로 개명(IDE 파일 이동이 아니라 신규 생성 후 이전 파일 제거 — 세션 중 명칭 자체가 여러 번 재검토된 결과라 순차 리네임 대신 최종 형태로 재작성).
- `Engine/Public/Math/Geometry.h`: `Sphere`(기존 유지, 필드 camelCase로 정리·주석에서 "컬링 목적상" 등 용도 언급 제거) + `AABB`/`OBB`/`Capsule`/`Quad` 신규 구현. 각 타입 `static X Transform(const X&, const Matrix4x4&)` 보유.
  - `AABB::Transform`: Arvo's method(8-corner 변환 없이 회전/스케일 성분 절댓값을 반너비에 가중합).
  - `OBB::Transform`: 로컬 axis 3개를 `TransformDirection`으로 변환 후 길이=스케일, `Normalized()`로 재정규화(0-스케일 방어, `Vector3::Normalized()` 기존 EPSILON 패턴 재사용).
  - `Capsule::Transform`: 두 끝점은 `TransformPoint`, 반지름은 Sphere와 동일하게 축 스케일 최댓값.
  - `Quad::Transform`: origin은 `TransformPoint`, row/col은 `TransformDirection`(방향+길이 벡터라 이동 제외).
- `Engine/Public/Math/Container.h`: `Plane` 구조체 신설(`normal`, `distance`, `DistanceToPoint()`, `Normalized()`). `Transform()`은 채택 안 함(§Compact Log 근거 참조) — Matrix4x4 정의 이후 위치로 배치.
- `Engine/Private/Math/Container.cpp`: `Plane::Normalized()` 구현 — `Vector2/3::Normalized()`와 동일 패턴(`length > Math::EPSILON`이면 정규화, 아니면 `Plane{Zero,0}`).
- `Agent/AgentLog/TODO.md`(Phase 4-3 Collider 항목 문구): "Sphere/AABB는 Phase 2 재사용" → "Sphere만 Phase 2 재사용, AABB·Capsule은 Collider에서 신규 정의"로 정정(계획서 §1-6 결정과 일치시킴).

### 결정 사항 요약

- `Geometry.h`는 **용도-중립적 순수 값 타입**만 담는다 — "컬링용" 같은 의미는 여기 두지 않고, 그 값을 소비하는 쪽(컬링 함수, Collider 교차 테스트)이 부여한다.
- `Plane`(무한 평면, 개념)과 `Quad`(유한 사각형, 도형)는 별도 타입으로 분리. `Plane`은 "감싸는 볼륨"이 아니라 "공간을 나누는 기준"이라 `Geometry.h`(기본 도형 모음)가 아니라 `Container.h`(순수 대수 구조, Vector/Matrix와 동일 층위)로 이동.
- `Plane::Transform`은 구현했다가 최종적으로 제거 — `Plane`의 유일한 실사용처(`Math::ExtractFrustumPlanes`, 아직 미구현)가 매번 view-proj에서 직접 평면을 뽑아내는 방식이라 "로컬 Plane을 월드로 옮긴다"는 파이프라인 자체가 성립하지 않음.
- 극단값(0-스케일) 방어는 이 코드베이스의 기존 관례(`Vector3::Normalized()`가 `length > EPSILON` 기준으로 조용히 Zero 반환, assert 없음)를 그대로 재사용.

## Compact Log #2 — 바운딩 볼륨 데이터 파이프라인 구현(TODO Phase 2 §1 "바운딩 볼륨 데이터 추가")

### 최종 설계

```
MeshData/SkinnedMeshData (localBounds 필드, 계산 지점 — Asset·Shape 두 경로의 공통분모)
    ↓ (복사)
MeshPrimitive/SkinnedMesh (localBounds 캐싱, GPU화 이후에도 값 유지)
    ↓ (Sphere::Merge로 서브메시들 병합)
WorldObject (localBounds 보관 + mutable worldBounds, AddToScene() 시 dirty면 Sphere::Transform 재계산)
    ↓ (복사)
RenderCommand::worldBounds (컬링이 나중에 참조할 자리 — CullCommands()는 아직 미구현)
```

### 수정/신규 파일

- `Engine/Public/Math/Geometry.h`: `Sphere::Merge(a, b)` 추가 — 두 구를 포함하는 근사 구(한쪽이 포함관계면 그대로, 아니면 두 중심을 잇는 직선상 표면점 중점/절반길이).
- `Engine/Public/Scene/Transform.h`: `bool IsDirty() const { return dirty; }` 추가 — 기존 `dirty`(private, `GetMatrix()` 호출 시 소비)를 소비하지 않고 확인만 하는 접근자.
- `Engine/Public/Mesh/MeshData.h`: `MeshData`/`SkinnedMeshData`(스켈레탈 쪽도 이 파일로 통합, 사용자가 직접 정리) 양쪽에 `Sphere localBounds` 필드. `Sphere ComputeBoundingSphere(const uint8_t* vertexData, uint32_t count, uint32_t stride)` 선언 — `PrimitiveVertex`/`SkinnedVertex` 둘 다 `pos`가 offset 0이라 이 함수 하나로 양쪽 다 처리.
- `Engine/Private/Mesh/MeshData.cpp`(신규): `ComputeBoundingSphere` 구현 — AABB min/max 1차 순회 → center 확정 → 중심에서 최대거리 2차 순회(`LengthSq` 누적, 마지막에 1회 `sqrt`). O(N), O(N²)(모든 정점 쌍 비교) 방식은 배제.
- `Engine/Public/Mesh/MeshPrimitive.h` / `.cpp`: `Sphere localBounds` + `GetLocalBounds()`. `Initialize()`에서 `data.localBounds` 복사 + `VA_LOG("Bounds", ...)`.
- `Engine/Public/Mesh/SkinnedMesh.h` / `.cpp`: 동일 패턴.
- `Engine/Private/Asset/MeshLoader.cpp`, `SkmLoader.cpp`: 벌크 `f.read()` 직후 `ComputeBoundingSphere` 호출해 `localBounds` 채움.
- `Engine/Private/Mesh/CubeShape.cpp`, `UVSphereShape.cpp`, `IcoSphereShape.cpp`: 정점 순회 없이 파라미터에서 O(1) 직접 계산(`CubeShape`는 `sqrt(hx²+hy²+hz²)`, UV/Ico Sphere는 이미 아는 `radius` 그대로).
- `Engine/Public/Object/WorldObject.h` / `.cpp`:
  - `Sphere localBounds`(private) / `mutable Sphere worldBounds` 필드.
  - `protected: void SetLocalBounds(const Sphere&)` — 파생 클래스가 채움.
  - `public: const Sphere& GetWorldBounds() const`.
  - `AddToScene(RenderScene&) const`는 그대로 public 유지, 내부적으로 `private: void AddToScene(RenderScene&, bool parentDirty) const`(오버로드, private) 호출.
  - dirty 판정: `transform.IsDirty() || parentDirty` — dirty면 `worldBounds = Sphere::Transform(localBounds, GetWorldMatrix())` 재계산 + `VA_LOG`, 재귀 시 계산된 `dirty` 값을 자식에게 그대로 전달(**형제 노드 간 dirty 소비 경쟁 버그 방지** — `Transform::GetMatrix()`가 dirty를 소비하므로, 재귀 시작 시점에 한 번 캡처한 값을 넘기지 않으면 첫 자식이 부모의 dirty를 먼저 소비해 둘째 자식이 놓침).
- `Engine/Public/Scene/RenderScene.h`: `RenderCommand::worldBounds` 필드. `AddMesh`/`AddSkinnedMesh` 시그니처에 `const Sphere& worldBounds` 파라미터 추가.
- `Engine/Private/Object/WorldModel.cpp`: `Initialize()`가 서브메시 로드 루프 안에서 `Sphere::Merge`로 로컬 바운드 누적 → `SetLocalBounds()`. `Impl_AddToScene()`이 `GetWorldBounds()`를 `scene.AddMesh(...)`에 전달.
- `Engine/Private/Object/WorldAnimatedModel.cpp`: 동일 패턴(`SkinnedMesh` 기준).

### 채택하지 않은 대안(반례 확인됨)

- **"가장 먼 두 정점(p0,p1)을 저장, 각 인스턴스가 스케일만 곱함"** — 비균등 스케일에서 과소 근사 위험. 반례: 로컬에서 X축으로 가장 먼 두 점(거리10) 외에 Y축으로 살짝(0.5) 튀어나온 정점이 있을 때 `scaleY=20`을 적용하면, 실제로는 그 튀어나온 점이 거리 10까지 벌어지는데(반지름 필요치 10) 두 점 방식은 여전히 반지름 5로 답함. `Sphere::Transform`이 "세 축 스케일 중 최댓값"을 쓰는 이유와 정확히 같은 문제.

## Compact Log #3 — 빌드 검증 진행 중, 남은 과제

### 빌드 이슈

- `C1075`(`Geometry.h:113`, `'{': 일치하는 토큰을 찾을 수 없습니다`) — 원인은 `Capsule::Transform` 함수 본문 시작에 끼어있던 빈 블록(`{ }`, 편집 중 실수로 추정). 사용자가 직접 제거.
- `E0018`(`Geometry.h:124`, `')'가 필요합니다`) — MSVC 컴파일러 오류 코드가 아니라 Visual Studio IntelliSense 오류 코드로 추정. 파일 재확인 결과 문법적으로 정상(중괄호 균형 20/20). 재빌드로 실제 컴파일러 메시지 확인 대기 중.

### 남은 과제(미착수)

1. **`BaseMesh` 리팩터링** — `MeshPrimitive`/`SkinnedMesh`가 필드(`vertexBuffer`/`indexBuffer`/`vertexByteSize`/`indexCount`/`vertexStride`/`localBounds`)와 `Initialize`/`Draw`/`DrawInstanced` 구현이 완전히 동일(차이는 `SkinnedMesh`의 본 팔레트뿐)함을 확인. `IMesh`(순수 인터페이스)는 유지하고 `BaseMesh : public IMesh`를 신설해 공통 구현을 옮기는 방향으로 합의했으나 아직 미착수.
   - `ComputeBoundingSphere`는 `BaseMesh`로 옮기지 않는다 — `MeshLoader`/`SkmLoader`/`PrimitiveShape` 계열(GPU 개념이 전혀 없는 CPU 전용 로더/빌더)이 호출하는 함수라, GPU 리소스 클래스인 `BaseMesh`로 옮기면 계층이 깨짐. `Mesh/MeshData.h`/`.cpp`(순수 CPU 레이어)에 유지.
2. **dirty 재귀 전파 방식 재검토** — 현재는 매 프레임 `AddToScene()` 재귀 시 `parentDirty` bool을 계산해 자식에 전달하는 방식(비용은 bool 계산+인자 전달 정도로 저렴). 사용자가 "Attach/Detach 시점에만 전달하면 되지 않냐"는 대안을 제시, "부모가 계속 움직이는 경우(카메라 붐 등)는 Attach 1회 전달로 커버 안 될 것 같다"는 우려를 전달하고 정확한 의도 재확인 중 — 결론 미확정.
3. **컬링 소비 로직 자체는 이번 범위 밖** — `RenderScene::CullCommands()`, `RenderScene` 프러스텀 토글, `SceneRenderer` 조립 지점은 TODO Phase 2 §1의 나머지 항목(다음 단계).
