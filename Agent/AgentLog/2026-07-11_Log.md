### G_Smith IBL k 분리 — 구현 완료

**배경**: IBL 착수 전 필수 선결 항목(`Plan_RenderQuality.md` 기술 부채 표). Cook-Torrance Smith 기하 감쇠 항의 k 값은 direct 조명(`k_direct = (roughness+1)^2/8`)과 IBL(`k_ibl = roughness^2/2`, Karis/UE4 remapping)에서 공식이 다른데, 기존 `G_Smith`는 k 계산을 함수 내부에 direct 공식으로 하드코딩하고 있어 IBL을 추가할 방법이 없었음.

**사전 확인**: `G_Smith`/`D_GGX`/`F_Schlick`를 직접 호출하는 곳은 없고, `DeferredLighting.hlsl`/`Transparent.hlsli`/`ForwardOpaque.hlsl` 전부 `EvalBRDF()`만 호출함을 grep으로 확인 — 수정 범위가 `Lighting.hlsli` 한 파일로 좁혀짐(`AnimationDemo.hlsl`도 매치되지만 죽은 코드라 제외).

**구현** (`Engine/_Shaders/Common/Lighting.hlsli`):
```hlsl
// 핵심 항은 k를 직접 받는다
float G_Smith(float NdotV, float NdotL, float k)
{
    float gv = NdotV / (NdotV * (1.0f - k) + k);
    float gl = NdotL / (NdotL * (1.0f - k) + k);
    return gv * gl;
}

// Direct 조명(Directional/Point/Spot)용 k
float G_Smith_Direct(float NdotV, float NdotL, float roughness)
{
    float r = roughness + 1.0f;
    float k = (r * r) / 8.0f;
    return G_Smith(NdotV, NdotL, k);
}

// IBL용 k = roughness^2/2 — IBL 구현 시 G_Smith_IBL 추가 예정(현재 호출부 없어 미추가)
```
`EvalBRDF()`의 `G_Smith(NdotV, NdotL, roughness)` 호출을 `G_Smith_Direct(NdotV, NdotL, roughness)`로 교체.

**특이사항**: 순수 리팩터링 — `G_Smith_Direct`가 기존과 동일한 k 공식으로 동일한 `G_Smith` 코어를 호출하므로 direct 조명 결과값에 수학적 변화 없음. `G_Smith_IBL`은 아직 호출부가 없어 추가하지 않음(CLAUDE.md: 사용되지 않는 추상화는 추가하지 않는다) — IBL 구현 시점에 함께 추가.

**다음**: IBL(Diffuse Irradiance Map + Specular LUT) 착수 가능.

**리마인드**: `AnimationRenderer::AddGraphicsPasses`/`AnimationPass`/`AnimationDemo.hlsl` — 정의만 있고 호출되지 않는 죽은 코드. 이번 작업과 무관하게 별도로 정리 필요(삭제 여부는 추후 판단).

### IBL Stage A (Diffuse Irradiance) — 구현 완료

**배경**: G_Smith k 분리 완료로 착수 가능해진 IBL의 첫 단계. Sky HDRI(`sundowner_overlook_4k.hdr`)는 배경 렌더링에만 쓰이고 조명(ambient)에는 전혀 반영되지 않고 있었음(기존 ambient는 `0.10f` flat 상수).

**사전 조사 결과** (`Sky.hlsl`, `ITexture`/`ITextureUAV`, `HelloCompute`/`AnimationRenderer::RenderCompute`, `ImmediateSubmit`, `DeferredLightingRenderer`, `RenderGraph` 전수 확인):
- Sky는 큐브맵이 아니라 **meshless triangle + LatLong(Equirectangular) 2D 텍스처** 방식(`Sky.hlsl`) — IBL도 이 레이아웃을 그대로 따름, 큐브맵 변환 불필요.
- `ITextureUAV::Create()`는 mip level을 항상 1로 고정(모든 텍스처 타입 공통) — RHI 전체의 공백.
- `IRenderDevice::ImmediateSubmit(recordFn)` — 이미 텍스처 업로드에 쓰이고 있는 동기(GPU 완료까지 블로킹) 1회 실행 경로. `RenderGraph`는 "1회만 실행" 개념이 아예 없음(`RenderGraph.h`/`.cpp` 확인 완료, 매 프레임 `Reset()`+재등록 구조) — IBL 프리컴퓨트는 RenderGraph를 거치지 않고 `ImmediateSubmit`으로 처리하는 것으로 확정.
- `RenderScene::skyTexture`는 매 프레임 새로 만들어지는 CPU 스냅샷이라 "이전에 계산했는지"를 기억 못함 — Engine 쪽(`IBLRenderer`)에 별도 비교용 캐시가 필요함을 확인.

**설계 논의 및 정정 사항**:
1. **mip level 회피(배열 슬라이스 우회) 철회**: 애초에 "더 큰 작업을 피하자"는 근거 없는 자체 판단이었음(사용자 지적, CLAUDE.md의 "임시 구현 금지" 원칙과도 배치). Stage A(Diffuse, roughness 축 없음)는 mip이 필요 없어 지금은 보류하되, Stage B(Specular Prefiltered) 착수 시 `ITextureUAV`에 실제 mip 체인을 제대로 추가하기로 확정(배열 슬라이스 lerp 같은 우회 없이).
2. **`IBLRenderer`를 컬렉션 관리형으로 설계**: `GBufferRenderer`/`ShadowMapRenderer` 등 기존 렌더러가 "하나의 인스턴스가 내부에서 여러 대상을 컬렉션으로 관리"하는 컨벤션을 따름 — 대상(스카이박스, 향후 Light Probe)마다 별도 인스턴스를 만들지 않고, `Precompute` 대상 텍스처를 파라미터로만 받아 `targets` 벡터에 append하는 구조. Light Probe(로컬 반사 캡처)가 생기면 같은 컨볼루션 파이프라인을 그대로 재사용 가능.
3. **`RecomputeGuard` 유틸리티 도입 후 철회**: 처음엔 "포인터가 바뀌었는지" 추적을 별도 템플릿 클래스로 분리하려 했으나, 2번 설계(컬렉션 관리)로 가면 `targets`를 조회하는 로직에 이 판단이 자연스럽게 흡수되어 별도 도구가 불필요해짐(사용자 지적 — "if 한 줄이면 되는 걸 도구화할 필요 없음"). 다만 포인터 비교 자체는 `SceneRenderer::AddPasses`가 매 프레임 호출되는 한 매 프레임 실행될 수밖에 없음(도구화 여부와 무관).

**구현 내역**:

| 파일 | 내용 |
|---|---|
| 신규 셰이더 | `Engine/_Shaders/DirectX/IrradianceConvolve.hlsl` — `Sky.hlsl`과 동일한 LatLong 역변환으로 출력 텍셀의 방향 N을 복원, 반구를 코사인 가중 리만 합으로 적분(LearnOpenGL IBL 레퍼런스와 동일한 `sampleDelta=0.025`, 텍셀당 ~15,800 샘플 — 1회성 프리컴퓨트라 실시간 비용 아님) |

### IBL Stage A — 버그 수정: 태양 방향 면 과다 발광

**증상**: 빌드 후 육안 확인 결과, 이전과 확연히 다른(정상적인) 조명 변화는 보였으나 **태양을 마주보는 면만 "빛나는" 것처럼 과다 발광**. 스키닝(Kachujin)·정적(Tower)·바닥(Cube) 전부 동일 증상(태양 반대쪽 면은 정상).

**오진 경로(기록으로 보존)**:
1. "너무 metallic해 보인다" → Tower `.matl`(레거시 Phong 포맷)에 애초에 `metallic=` 키가 없어 `MaterialData` 기본값(0.0) 그대로임을 확인 — 재질 값 문제 아님.
2. Directional Light 세기 조정·완전 비활성화 → 정도만 다를 뿐 증상 지속 → Directional Light 무관 확정.
3. `irradiance *= 0.2f` 배율 조정(사용자 실험) → 그래도 지속 → 단순 노출 과다가 아님.
4. "픽셀 단위로 번들거리는가?"(Normal Map/TBN 버그 의심) → `GBufferSkinned.hlsl`의 TBN 구성 검토(수식상 문제 없음) → 사용자 확인: **바닥(Normal Map 없음)도 한쪽 면 전체가 균일하게 발광** → 픽셀 단위 노멀 버그 아니라 **평평한 면 전체가 특정 방향(태양)을 보면 발광**하는 패턴으로 재확정.

**근본 원인**: 이 씬은 이미 태양을 표현하는 Directional Light를 별도로 갖고 있는데, `IrradianceConvolve.hlsl`이 HDRI 원본을 **클램프 없이** 그대로 적분한다. HDRI의 태양/헤이즈 영역 raw 값은 수백~수천에 달할 수 있어, 태양을 마주보는 면은 Directional Light와 **중복으로 태양 에너지를 한 번 더** 받는 셈이 되어 극단적으로 밝아짐. Diffuse Irradiance는 "부드러운 하늘 반사광"만 담당해야 하는데 태양 자체를 다시 적분해 넣은 것이 문제.

**수정** (`Engine/_Shaders/DirectX/IrradianceConvolve.hlsl`) — 컨볼루션에 들어가는 원본 샘플 자체에 상한을 걸어 태양 성분을 제한(태양은 Directional Light가 별도 담당하므로 이 클램프와 무관하게 직접광은 그대로 유지):
```hlsl
const float kMaxSampleContribution = 8.0f;
...
float3 sampleColor = gSourceHDR.SampleLevel(LinearSampler, sampleUV, 0).rgb;
sampleColor        = min(sampleColor, kMaxSampleContribution.xxx);
irradiance += sampleColor * cos(theta) * sin(theta);
```
`8.0f`는 초기값이라 임의적 — 육안 검증 후 튜닝 필요할 수 있음. 사용자가 임시로 넣었던 `irradiance *= 0.2f`(사후 스케일링, 근본 해결 아님)는 제거.

### IBL — 스카이박스 없을 때 계산 자체 스킵 플래그 추가

**요구사항**: 스카이박스가 없으면 IBL 계산(컴퓨트 디스패치)이 아예 실행되지 않아야 함.

**변경**:
- `IBLRenderer::Initialize()` — 폴백 텍스처(`defaultIrradiance`)는 리소스만 생성하고 컴퓨트 디스패치는 실행하지 않음(기존에는 1x1 상수 소스로 실제 컨볼루션을 1회 돌렸었음). 더 이상 쓰이지 않는 `defaultSourcePanorama`도 함께 제거.
- `CB_DeferredCamera`(C++ `DeferredLightingRenderer.cpp` / HLSL `DeferredLighting.hlsl` 양쪽)에 `iblEnabled`/`IBLEnabled` 필드 추가(기존 padding 자리 재사용, 버퍼 크기 불변).
- `DeferredLighting.hlsl` — `IBLEnabled == 0`이면 `gIrradiance`를 아예 샘플링하지 않고 IBL 이전의 flat ambient(`0.10f`) 상수로 대체. 폴백 텍스처의 미정의 내용이 실제로 읽히는 경로가 없음(barrier 추적은 여전히 정확하게 걸림 — 상태 추적과 내용 유효성은 별개).
- `SceneRenderer::AddPasses` — `iblEnabled = (iblHandle != IBLRenderer::kInvalidHandle)` 계산 후 `DeferredLightingRenderer::AddPasses`/`Dispatch`까지 전달.

**상태**: 구현 완료, 육안 검증 완료.

## Compact Log #4

### IBL Stage B (Specular Prefiltered Map + BRDF LUT) + Forward 경로(Transparent) IBL 적용 — 구현 완료

**배경**: `PhongToPBR_Migration.md` §9 재평가에서 IBL이 "Deferred 경로 Diffuse만 부분 해결"로 남아있음을 확인. 사용자가 SSAO보다 IBL Stage B + Forward 경로 적용을 우선순위로 지정.

**사전 조사로 밝혀진 사실**:
1. **RHI 밉 지원 부재** — `ITextureUAV::Create()`(`TextureUAV_DirectX.cpp`)가 `MipLevels = 1`로 하드코딩, UAV/SRV 디스크립터도 1개뿐. Specular Prefiltered Map은 밉마다 다른 roughness를 담는 밉체인이 필수라 RHI 확장이 선행되어야 함.
